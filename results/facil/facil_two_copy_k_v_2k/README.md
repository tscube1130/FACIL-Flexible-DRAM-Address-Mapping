# K/V shared mapping versus two-copy placement

This experiment uses one 1024 × 4096 FP16 K/V matrix and the [corrected DRAMsim3 timing proxy](../../../configs/LPDDR5_6400_APPROX_v1.ini). Both scans issue the same 65,536 128-byte READs with matching logical offsets and arrival cycles. The PIM-compatible region starts at 0x0 and uses MapID 2. The second region starts at 0x10000000 and uses conventional decoding. Both runs load the same four-page registry. The paired regions represent equal logical weights through their offsets. DRAMsim3 simulates the requests and their placement.

| Metric | FACIL mapped scan | Duplicated layout, conventional scan |
| --- | ---: | ---: |
| Completed reads | 65,536 | 65,536 |
| Requested bytes | 8,388,608 | 8,388,608 |
| First full-completion cycle budget | 590,416 | 132,517 |
| Simulated read time | 184.505 µs | 41.412 µs |
| Effective throughput | 45.465 GB/s | 202.567 GB/s |
| Calculated full-model linear-weight storage | 13 GiB | 26 GiB |

The conventional scan is 4.455× faster for this workload. The calculated storage scales the two-copy assumption to 224 FP16 linear projections. GPU kernels, PIM arithmetic, and full inference are outside the measured scope.

The placement audit checks every request-sized offset in each region, for 131,072 unique native DRAM tuples. It compares the mapped region against the Python reference, the conventional region against a registry-free native configuration, and an interleaved trace against expected reads on all four channels. Each scan's cycle budget is checked again at one cycle less. ## Replay

Build the simulator and install the Python requirements as described in [Reproducibility](../../../docs/REPRODUCIBILITY.md#build-and-meaningful-checks). From the repository root, choose a new output directory and run:

```bash
out=build/two-copy-replay
python -B experiments/facil/two_copy_k_v.py "$out"
saved="$PWD/results/facil/facil_two_copy_k_v_2k/run"
diff -u "$saved/duplication_vs_facil.csv" "$out/duplication_vs_facil.csv"
diff -u "$saved/placement_validation.json" "$out/placement_validation.json"
(cd "$out" && sha256sum -c "$saved/scan_trace_sha256.txt")
```

The two full scan traces are regenerated by the runner. Their [original SHA-256 checksums](run/scan_trace_sha256.txt) are retained. The replay checks the completion boundary and writes new raw simulator statistics in the output directory.
